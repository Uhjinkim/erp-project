# 급여 모듈 UI 개선 보고서

- 작업일: 2026-09-23
- 작업 범위: 급여 생성·조회 화면 개선(백엔드 API 확장 포함)
- 계기: 사용자가 스키마 불일치 수정 이후 추가로 요청한 4가지 UI/기능 개선
- 참고: 같은 날짜의 `2026-09-23_급여_레거시_스키마_불일치_수정_보고서.md` 이후 작업이다.

## 1. 요청 사항과 반영 내용

### 1) 급여 생성 시 모든 구성항목을 선택형이 아니라 직접 입력하게, 비우면 저장 안 되게

- `POST /api/payroll/statements/`가 `items` 배열을 선택적으로 함께 받을 수 있도록
  확장했다(`payroll/application/dto.py`의 `CreateStatementCommand.items`,
  `payroll/presentation/serializers.py`의 `CreateStatementSerializer.items`). 급여
  생성과 구성항목 입력을 한 번의 요청으로 처리한다.
- 프론트엔드 급여 생성 폼은 더 이상 항목을 하나씩 드롭다운으로 골라 추가하는 방식이
  아니라, 활성 구성항목 전체(지급/공제로 구분)를 라벨이 붙은 입력창으로 한 번에
  보여준다. 값을 비워두면 그 항목은 아예 저장하지 않는다(`ComponentAmountFields`
  컴포넌트). 기존에 이미 만들어진 급여의 "구성항목 편집"도 동일한 방식으로 바꿨다.

### 2) 상여 등 항목 추가

- 항목을 앱 화면에서 직접 새로 등록하는 기능(예: "새 구성항목 만들기" 화면)은 이번에
  만들지 않았다 — 대신 사용자가 제시한 대안대로 "상여"(`BONUS`, 지급)를 새 데이터
  migration(`payroll/migrations/0004_seed_bonus_component.py`)으로 추가했다. 화면은
  활성 구성항목을 API에서 그대로 받아와 보여주므로, 상여는 별도 프론트엔드 수정 없이
  바로 급여 생성/편집 화면에 나타난다.
- 향후 항목이 더 필요하면 Django admin(`/admin/`)에서 급여 구성항목을 직접 추가·
  비활성화할 수 있다(이미 등록되어 있던 기능). 더 많은 기본 항목이 필요하면 알려주면
  이번처럼 migration으로 추가하겠다.

### 3) "내 급여" 화면을 급여명세서 형식으로

- 첨부한 이미지의 구조(지급내역(A)/지급액, 공제내역(B)/공제액 2단 표, 지급총액·
  공제액 계·차인지급액(C))를 그대로 반영한 `PayslipTable` 컴포넌트를 만들었다.
  상단에는 성명·직급·사번·지급일을 표시한다.
- **주민등록번호는 표시하지 않았다.** 현재 시스템에는 사원의 주민등록번호를 저장하는
  필드가 전혀 없다(개인정보보호 상 민감정보라 별도 암호화·마스킹 정책 없이 추가하는
  것은 위험하다고 판단했다). 이미지의 형식 중 표 구조와 요약 행만 반영했다. 필요하면
  별도로 논의해서 저장 정책을 먼저 정한 뒤 추가하는 것이 안전하다.
- 이 급여명세서 형식은 "내 급여"뿐 아니라 "급여 관리" 탭에서도 동일하게 사용해
  급여담당자도 같은 형태로 확인할 수 있게 했다.
- 성명·직급을 보여주기 위해 백엔드 응답에 `employee: {emp_no, name, position_name}`
  필드를 추가했다(`payroll/presentation/views.py`의 `_serialize_statement(s)`,
  workforce의 `Employee`/`Person`/`Position`을 조회 전용으로 join).

### 4) 사번 입력 대신 부서 > 사람 선택

- "급여 관리" 탭의 조회 필터와 "급여 생성" 폼의 대상자 선택을 모두 부서 선택 →
  해당 부서 사람 선택의 2단 드롭다운으로 바꿨다. 기존 workforce API
  (`/api/workforce/departments/`, `/api/workforce/employees/`)를 그대로 재사용했고
  백엔드 변경은 없다.

## 2. 변경 파일

- Backend: `payroll/application/dto.py`, `payroll/application/service.py`,
  `payroll/infrastructure/repositories.py`(생성 시 구성항목도 함께 저장하도록 수정),
  `payroll/presentation/serializers.py`, `payroll/presentation/views.py`,
  `payroll/migrations/0004_seed_bonus_component.py`(신규)
- Tests: `tests/test_payroll_api.py`에 생성 시 구성항목 동시 입력 및 `employee` 요약
  응답을 검증하는 테스트 추가
- Frontend: `types/payroll.ts`, `api/payroll.ts`, `components/PayrollPanel.tsx`(전면
  개편), `styles.css`

## 4. 참고 사항

공유 개발 DB의 `payrolls` 테이블에 사번 910028, 910014의 2026년 9월분 급여가 이미
`확정` 상태로 2건 존재하는 것을 확인했다. 사용자가 서버 재시작 후 기존(이번 UI
개선 전) 화면으로 직접 테스트한 결과로 보이며, 이번 작업에서 만든 것이 아니다.
정리가 필요하면 말씀해 주시면 삭제하겠다 — 임의로 지우지 않았다.

## 5. 후속 제안

- 구성항목을 화면에서 직접 추가·수정하는 관리 UI가 필요하면 별도로 만들 수 있다
  (현재는 Django admin 또는 migration으로만 추가 가능).
- 주민등록번호 등 민감 개인정보를 급여명세서에 표시하려면, 저장 여부·암호화·마스킹
  정책을 먼저 정해야 한다.
