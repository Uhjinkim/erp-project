- 기준: dev 작업 트리. 기존 배포·DB 최적화·역할 UX 변경을 보존했다.
- 요청: SSH 경유 상태 점검의 대기 여유 확대와 어색한 메뉴 검색 배치 수정.
- Notion 조회·수정, 제품 권한·업무 규칙 변경 없음.

## 상태 점검

이전 직접 Redis PING은 약 3.89초에 성공했으나 health 접속/읽기 제한이 1초여서
실패했다. 개발 설정의 HEALTH_CHECK_TIMEOUT_SECONDS 기본값을 10.0으로 변경했다.
환경 예제와 현재 로컬 개발 환경의 해당 숫자만 함께 갱신하고 표준 통합 서버를 재시작했다.
자격증명·그 외 로컬 설정은 변경하지 않았다. 환경변수의 명시적 값은 계속 우선한다.
운영 설정·운영 예제의 기본 제한은 이번 개발 SSH 지연 보정에서 변경하지 않았다.

설정값은 Redis 클라이언트의 socket_connect_timeout과 socket_timeout 각각에 적용된다.
health API 전체의 총 제한시간·업무 API 제한시간을 뜻하지 않는다. 공통 상태 UI·폴링은
이전 요청대로 제거된 상태이며 이번 수정으로 다시 추가하지 않았다.

재시작 뒤 실제 GET /api/health/는 약 5.5초에 HTTP 200/online을 반환했고
backend/database/redis/workforce 모두 connected였다. 원격 지연이 늘어나면 다시 실패할 수
있으며 이번 단일 측정을 일반적인 응답시간 보장으로 해석하지 않는다.

## 메뉴 검색 배치

검색을 왼쪽 탐색 영역 맨 위로 옮겼다. 별도 폼 라벨과 큰 입력 대신 36px 높이의 검색 아이콘·
안내문구 입력을 배치하고, 모듈 제목과 메뉴 목록을 그 아래에 이어 붙였다.
입력 최소 폭을 0으로 두어 좁은 탐색 영역에 맞게 축소한다. 연결된 숨김 label과 영역 설명,
포커스 표시를 유지한다. 기존 활성 모듈·역할별 메뉴 필터 동작은 보존한다.

브라우저에서 실제 AppShell을 합성 HR 사용자와 정적 본문으로 임시 마운트해 검수했다.
업무 API를 mock하거나 실제 계정·업무 데이터를 수정하지 않았다. 검수 DOM은 제거하고
원래 앱을 새로고침했다. 로그인·업무 전체 흐름 재검수와는 구분한다.

- 별도 iframe 1200/980px: 검색이 모듈 제목 위에 있고 가로 넘침 없음.
- 별도 iframe 360px: 모바일 메뉴 토글 표시·기본 닫힘·가로 넘침 없음.
- 실제 554px 뷰포트: 화면 메뉴 열기, 검색어 ‘부서’ 입력 시 해당 메뉴만 표시.
- 같은 모바일 레이아웃의 컨테이너 360px: 열린 메뉴 안에 검색창이 들어가고 가로 넘침 없음.
- 검색 결과 없음 안내, 연결된 접근성 label, 입력 포커스와 테두리 표시 확인.
