## 1. 우선순위별 처리 결과

| 순서 | 문제 | 보완 결과 |
| --- | --- | --- |
| 1 · 높음 | 일반 사원에게 평가·급여 관리 메뉴 노출 | 평가 HR 메뉴는 HR_MANAGER, 급여 관리 메뉴는 PAYROLL_MANAGER, 개인정보 처리함은 HR_MANAGER 또는 superuser에게 제공 |
| 1 · 높음 | 역할과 무관한 평가 기본 진입 | 부서장은 팀 평가, HR 관리자는 평가 관리, 나머지는 내 평가로 진입. 겸직 부서장은 팀 평가 우선 |
| 2 · 높음 | 급여 상단 선택기에서 본인 선택 후 저장 시 403 | 생성용 선택기의 본인 option 비활성·사유 표시, 대상 미선택 시 금액 입력·저장 비활성, 선택·제출 함수도 본인 차단 |
| 2 · 높음 | 본인 급여 직접 편집 URL 안내 부족 | 본인 작성중 급여의 목록 액션은 보기로 표시, 편집 버튼 비활성 유지, 사전 안내와 저장 경로의 본인 방어 추가. 조회 필터는 본인 포함 유지 |
| 3 · 높음 | 슈퍼유저의 사원·조직 UI/API 불일치 | 사용자 선택에 따라 메뉴 등록과 내부 화면 판정 모두 HR_MANAGER 또는 superuser 허용. 백엔드 권한 확대 없음 |
| 4 · 중간 | 홈·계정 관리의 준비 중 화면 | 배포 모듈 등록에서 홈·시스템 제외, 브랜드 링크는 내 정보로 이동. 신규 집계·계정 UI를 만들지 않음 |

상세·처리 화면은 목록에서 대상을 고른 뒤 진입하도록 독립 메뉴에서 숨겼다. 예전 평가 작성자·
승인 담당자가 기존 링크를 열 수 있도록 평가 작성·휴가 처리 라우트 자체는 유지했다. 현재 부서장
여부만으로 이미 담당한 신청의 처리 권한을 새로 차단하지 않는다. 실제 업무 권한·상태는 서버 기준이다.
권한 없는 관리 URL에는 접근 안내, 해당 모듈의 이용 가능한 화면 링크와 본인 메뉴를 표시한다.

평가의 HR 겸직 작성·제출 및 본인 작성 평가의 HR 처리 제한은 선행 검수의 현재 동작을 유지한다.
사원 미연결 계정에는 평가 API를 호출하기 전에 연결 필요 안내를 표시한다.

## 2. API·설계·배포 영향

로그인·현재 사용자 응답에 읽기 전용 boolean `is_department_head`를 추가했다. 자신의 소속 부서뿐
아니라 다른 부서에 부서장으로 지정된 경우도 true다. 연결 사원이 없으면 false다. 직급명이나 역할명으로
부서장을 추측하지 않는다. 기존 평가 gateway와 같은 현재 Department.head 기준이며, 인증 정보를
업무 처리의 최종 권한으로 사용하지 않는다. frontend에서는 누락된 필드를 false로 처리한다.

accounts presentation은 workforce application 서비스·Protocol과 infrastructure gateway를 통해
부서장 정보를 조회한다. domain에 ORM·Django 의존성을 추가하지 않았다. 사원이 연결된 인증 응답에
Department EXISTS 조회 1회가 추가된다. 폴링은 없으며 DB 재사용·N+1 최적화와 성능 실측은 별도 범위다.

- backend와 frontend를 함께 배포하거나 backend를 먼저 반영해야 부서장 메뉴가 정상 표시된다.
- DB 모델·migration·환경변수·패키지·lockfile 변경 없음.
- workforce의 기존 서버 superuser 예외 유지. 급여 서비스는 PAYROLL_MANAGER 역할을 실제로
  검사하므로, superuser만 있는 계정에 급여 관리 화면을 열던 기존 프론트 판정도 서버와 맞췄다.
  사원·조직 화면 허용 결정을 다른 업무의 권한 확장으로 적용하지 않았다.
- 홈·시스템의 예전 직접 주소는 등록되지 않은 화면 안내를 표시한다. 배포 등록은 6개 모듈·30개 화면.
- 공통 전시·연결 상태 화면과 health 폴링은 제거된 상태를 유지한다.

## 3. 실제 브라우저 재검수

선행 검수의 격리 SQLite·실제 세션·CSRF 환경을 유지하고 변경된 API 서버를 재시작했다.
검수 주소는 localhost:5174이며 공유 PostgreSQL·Redis 쓰기·migration은 수행하지 않았다.
자기 급여 직접 URL 검수를 위한 합성 급여는 별도 담당자 fixture로 격리 DB에 준비했다.

| 계정 | 확인 결과 |
| --- | --- |
| 일반 사원 | 평가 하위 메뉴는 내 평가, 급여 하위 메뉴는 내 급여명세만 표시. 급여 생성 직접 URL은 접근 안내, 후속 링크는 내 명세로 이동 |
| 부서장 | 인사평가 레일 클릭 시 팀 평가 진입. 팀 평가·내 평가 메뉴 표시, HR 메뉴 숨김. 기존 작성 평가·작성 대상 조회 유지 |
| 급여 담당자 | 본인 부서 선택 시 본인 option disabled 확인. 대상 미선택 금액·저장 비활성. 다른 사원 선택 후 300만원 급여 작성중 저장 성공 |
| 급여 담당자 | 본인 작성중 명세 직접 URL에 자기 처리 안내, 편집 버튼 disabled, 목록은 보기로 표시 |
| HR 겸직 부서장 | 팀 평가·평가 관리·내 평가 메뉴, 개인정보 수정 요청 처리함, 사원·조직 메뉴 표시 |
| HR 역할 없는 슈퍼유저 | 사원·조직 메뉴 표시, 사원 목록 9명과 사원 상세 조회 성공 |
| 사원 미연결 계정 | 평가 화면에서 사원 연결 안내. 홈·시스템 레일 없음, health 리소스 요청 0 |

이번 재검수는 변경된 메뉴·차단 경로 중심이다. 모든 역할의 모든 쓰기 조합·모바일 레이아웃·
출력 파일 내용·공유 DB 성능·동시 처리·운영 배포 연결을 재검수한 것은 아니다.
