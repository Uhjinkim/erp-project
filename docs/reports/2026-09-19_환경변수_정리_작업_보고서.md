# 환경변수 정리 작업 보고서

- 작업일: 2026-09-19
- 작업 범위: SSH 터널, Backend 개발·운영, Frontend 개발·운영 환경변수 예제와 스크립트
- 원칙: 비밀값 파일은 수정하거나 출력하지 않고 예제와 로딩 코드만 정리

## 1. 점검 결과

루트 `.env.example`은 SSH 터널 스크립트 전용이지만 `DB_PORT`라는 이름을 사용해 Backend의
`DB_PORT`와 의미 범위가 겹쳤다. 루트 값은 SSH 포워딩의 로컬 포트이고 Backend 값은 Django가
접속할 데이터베이스 포트이므로 값은 보통 같더라도 설정 책임이 다르다.

Backend와 Frontend의 개발·운영 예제는 서로 다른 디렉터리에서 로드되며, Frontend는 브라우저에
노출 가능한 `VITE_` 변수만 사용한다. 비밀값이 Frontend 예제로 섞인 사례는 없었다.

## 2. 변경 내용

SSH 터널 변수는 다음과 같이 명확한 전용 이름으로 변경했다.

- `DB_PORT` → `DB_TUNNEL_LOCAL_PORT`
- `DB_REMOTE_HOST` → `DB_TUNNEL_REMOTE_HOST`
- `DB_REMOTE_PORT` → `DB_TUNNEL_REMOTE_PORT`
- `REDIS_PORT` → `REDIS_TUNNEL_LOCAL_PORT`
- `REDIS_REMOTE_HOST` → `REDIS_TUNNEL_REMOTE_HOST`
- `REDIS_REMOTE_PORT` → `REDIS_TUNNEL_REMOTE_PORT`

macOS/Linux 셸 스크립트와 Windows PowerShell 스크립트의 기본값, 허용 키, 포트 검증,
SSH `-L` 인자와 실행 안내를 모두 새 이름으로 변경했다. 이전 이름이 실제 루트 `.env`에 남아
있으면 기본값으로 조용히 실행하지 않고 변경 안내와 함께 중단하도록 했다. Backend의 `DB_HOST`,
`DB_PORT`, `REDIS_URL`은 애플리케이션 접속 설정이므로 그대로 유지했다.

코드와 예제의 정합성을 맞추기 위해 Backend 개발 예제에 오프라인 SQLite 경로 선택 항목
`DEVELOPMENT_SQLITE_PATH`를 주석 예시로 추가했고, Frontend 운영 예제에
`VITE_AUTH_MODE=session`을 명시했다.

## 3. 환경별 책임

- 루트 `.env`: SSH 접속 정보와 로컬 포워딩 설정만 보관
- `backend/.env.development`: 개발 Django, 터널의 로컬 DB·Redis 접점, 오프라인 모드 설정
- `backend/.env.production`: 운영 Django, 실제 DB·Redis 접속 설정
- `frontend/.env.development`: 개발 UI와 오프라인 시뮬레이션에 필요한 공개 설정
- `frontend/.env.production`: 운영 빌드에 포함 가능한 공개 설정과 세션 인증 모드

실제 `.env` 파일은 자동 변경하지 않았다. 기존 루트 `.env`를 사용 중이면 위 변경표에 따라
터널 변수 이름을 옮겨야 한다. SSH 비밀번호는 환경 파일이나 실행 인자에 저장하지 않는다.

## 4. 검증

- 환경변수 예제 간 동일 키 재점검
- 두 터널 스크립트의 실행 설정에서 이전 이름을 제거하고 변경 안내에만 남았는지 확인
- POSIX 셸 구문 검사
- Django system check와 Ruff 검사
- Frontend ESLint, TypeScript production build
- Git whitespace 검사

공유 PostgreSQL과 Redis에는 연결, migration, seed 또는 데이터 변경을 수행하지 않았다.
현재 검증 환경에는 PowerShell 실행기가 없어 `.ps1` 런타임 파서 검사는 수행하지 못했다.
