# 휴가 신청 시간 기본값과 분 단위 입력

- 일자: 2026-10-29
- 범위: dev의 vacation 신청·재신청 프론트엔드
- 근거: 사용자의 시작 09:00 이후 선택, 초 00 고정, 기본 시작 09:00·종료 18:00 요청

신규 신청과 저장 후 새 신청은 브라우저 현지 오늘 날짜의 09:00~18:00으로 초기화한다.
재신청은 기존 날짜와 시·분을 유지한다. datetime-local 입력은 60초 단위이며 값에서도 초를
제거하여 초 선택을 표시하지 않는다. 선택한 시작 날짜의 09:00을 최소값으로 두고,
폼 검증에서도 현지 시간 09:00 이전을 차단한다. 날짜 변경에도 해당 날짜의 09:00을 적용한다.
종료 18:00은 기본값이며 사용자가 종료 시간을 변경할 수 있다.

전송 변환은 신규·재신청 모두 초와 밀리초를 0으로 정규화한 ISO 값을 만든다.
신청·재신청 편집 이외의 기존 이력 표시와 서버의 날짜 검증/API 계약은 변경하지 않았다.
이번 09:00 제한은 신청 화면 입력 제약이며 서버 전체의 새로운 업무 불변식으로 추가하지 않았다.
사용 일수는 기존처럼 서버 제공 유형 단위와 사용자 입력을 따르며 시간차로 자동 계산하지 않는다.

## 검증

- 휴가 집중 테스트 12개, 프론트 전체 테스트 65개 통과.
- 오늘의 자정 근처 기본값, 날짜별 08:59 거부·09:00 허용, 기존 시·분 유지,
  초·밀리초 제거와 전송 ISO 정규화를 회귀 검증했다.
- UTC 환경에서도 휴가 집중 테스트 12개 통과하여 로컬 날짜/시간 처리를 확인했다.
- 프론트 lint/build 및 git diff --check 통과.
- 이번 변경의 실제 브라우저 검수는 수행하지 않았다.
- 공유 DB/Redis 쓰기, 스키마 변경, 사용자 개발 서버/8080의 시작·중지·재시작 없음.

대체했다. 기기 시간대와 관계없이 Asia/Seoul 기준이며 초 00 고정은 유지한다.
