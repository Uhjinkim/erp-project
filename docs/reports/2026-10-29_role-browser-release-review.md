# 배포 전 역할별 브라우저 검수와 개발 UI 제거

- 검수일: 2026-10-29
- 기준: dev 5dc4415 위 작업 트리. 기존 배포 설정·문서 변경은 보존했다.
- 요청 범위: 현재 업무 화면의 역할별 사용 흐름 검수, 공통 컴포넌트 전시·연결 상태 UI 제거.
- 결론: 아래 주요 성공 흐름은 실제 브라우저와 Django API로 확인했다. 역할별 메뉴 정리와
  기존 준비 중 화면 등 잔여 항목이 있어 전체 배포 승인 또는 모든 업무 시나리오 통과를 뜻하지 않는다.

## 1. 검수 환경과 데이터 경계

기존 개발 서비스와 별도로 프론트 localhost:5174, Django localhost:8001을 띄웠다.
Django test settings를 바탕으로 임시 파일 SQLite에 스키마·합성 계정·부서·사원·역할·연차·급여
데이터를 준비했다. 휴가는 database 통합 모드, 인증은 실제 세션·쿠키·CSRF를 사용했다.
공유 PostgreSQL·Redis에는 migration·계정 생성·업무 데이터 쓰기를 수행하지 않았다.
검수용 fixture 생성과 초기 휴가 승인·회수, 이전 월 급여 생성은 격리 SQLite에만 수행했다.
Notion 조회·수정은 수행하지 않았다.

단순 API 응답 mock 검수가 아니다. 아래 브라우저 작업은 프론트 폼·버튼과 실제 Django API를
사용한다. 다만 SQLite는 실제 PostgreSQL 스키마·네트워크 지연·잠금·운영 Redis를 재현하지 않는다.
운영 부하·공유 DB 성능·배포 연결 성공 여부는 이번 검수로 판단할 수 없다.

상세 성능·사용 흐름 검토는 [선행 검토](./2026-10-29_release-flow-performance-review.md)와 함께 본다.

## 4. 제거한 UI와 호출

- 앱 공통 연결 상태 요약·상세, 수동 연결 확인·개발 오프라인 제어, 공통 경고 제거.
- useConnection 및 주기적인 /api/health/ 호출 제거. 업무 진입 시 health 응답을 기다리지 않는다.
- system-health 화면 등록 제거. 시스템 기본 화면은 기존 account-admin 준비 중 화면이다.
- 공통 컴포넌트 전시 화면·메뉴·개발 직접 진입 경로 제거. 기존 업무 공통 UI는 유지.
- 관련 타입·컴포넌트·스타일·환경변수 예제·타입 선언 제거. 로컬 개인 환경 파일은 변경하지 않았다.
- 업무별 API 오류·재시도, 로그인 인증 서버 오류 처리는 유지. 백엔드 health API는 운영 진단용으로 유지.

브라우저 리소스 기록의 /api/health/ 요청 수는 0이며, 공통 전시·서비스 연결 상태·오프라인 테스트
문구가 DOM에 없는 것을 확인했다. 휴가의 ‘서버 상태 새로고침’은 해당 신청 데이터를 재조회하는
업무 버튼으로 유지한다. 이번 변경으로 health 폴링 비용과 선행 대기는 제거했으나 DB 연결 재사용·
N+1 쿼리는 변경하지 않았으므로 실제 개발환경 응답시간 개선 수치를 주장하지 않는다.

## 5. 검증과 한계

- frontend: bun run test 54개 통과, bun run lint 통과, bun run build 통과.
- 회귀 검사: 제거한 진단 경로 미등록, 모듈 진입에 health 인자 불필요·업무 enabled 전달 확인.
- 기존 사용자 변경이 있는 작업 트리의 diff·status를 검토했다. 의존성·백엔드·스키마 변경 없음.
- 백엔드 소스를 변경하지 않아 이번 변경의 백엔드 전체 검사를 재실행하지 않았다.
- 브라우저 자동화에서 새 datetime-local 값 입력이 정상 적용되지 않아 신규 휴가 날짜 입력은
  완주하지 못했다. 이를 제품 오류로 판정하지 않았다. 격리 fixture로 회수 상태와 날짜를 준비한 뒤
  브라우저에서 재신청·부서장 승인을 수행했다. 신규 사원 등록도 필수값 오류까지만 확인했다.
- 급여 PDF/인쇄·xlsx 파일 내용, 모바일·다른 브라우저·키보드 접근성 전체 검수는 미수행.
- 공유 인프라 쓰기·migration·배포·외부 메시지 발송 없음.
