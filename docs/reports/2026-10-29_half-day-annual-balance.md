# 반차의 연차 잔여 공유

- 날짜: 2026-10-29, 브랜치 dev
- 근거: 사용자 명시 요구. 반차는 별도 잔여 없이 연차에서 사용 일수만 다르게 소비한다.
- 추적: LV-001, FN-LV-001/007. 저장소 스냅샷에 사용자 확정 사항을 기록했으며 Notion 원문 갱신 없음.

## 구현

순수 domain의 `balance_type_id`가 HALF를 ANNUAL로 매핑한다. DB 어댑터는 목록 일괄 조회,
개별 신청 검증, 승인 시 잠금·차감, 회수 복원 모두 동일한 연차 행을 사용한다. 반차 행이 없어도
연차 잔여를 읽고, 별도 반차 행이 존재하더라도 신규 처리에서 독립 잔여로 사용하지 않는다.
일괄 조회의 잔여 SELECT는 계속 1회다. 부족 시 신청/승인 모두 기존 예외를 적용한다.

개발 설정 어댑터도 ANNUAL 설정을 사용하고 승인된 연차·반차의 실제 차감 사용량을 합산한다.
두 유형의 승인 잠금은 같은 연차 유형 행으로 일치시켰다. 대기 신청은 기존처럼 예약 차감하지 않는다.
차감 값은 제출한 use_days 그대로이며 반차 계수를 이중으로 곱하지 않는다.

유형 DTO에 balance_type_id를 포함하고 HALF의 공유 잔여를 안내한다. 유형 변경 시 서버가 내려준
양수 deduct_days를 기본 사용 일수로 설정한다(반차 0.50, 연차 1.00). 저장된 신청의 최초 수정
진입은 기존 일수·일정·사유를 유지한다. 유형 전환에 추가 네트워크 요청은 없다.

- 반차 승인 0.5 차감·회수 0.5 복원, 대기 미차감, 연차 승인 시 반차 사용량 반영 및 부족 거부.

  연차 전환 시 같은 잔여와 기본 1.00일, 추가 fetch 0회 확인. 임시 검수 파일 제거.

## 배포 및 데이터 영향

모델/마이그레이션 변경 없음. 공유 개발 DB `erp_dev.public`의 55명에 대해 별도 `HALF`
잔여 55건(합계 43.00일)을 각 사원의 `ANNUAL` 잔여에 합친 뒤 `HALF` 행 55건을 한
트랜잭션에서 삭제했다. 결과는 `ANNUAL` 잔여 55건(합계 715.50일), `HALF` 잔여 0건이다.
기존 승인 신청 35건(반차 11건)과 처리 이력 70건은 변경하지 않았다. 이는 해당 공유 개발 DB의
확인된 테스트 데이터만 대상으로 한 보정이며 다른 환경에 일반화하지 않는다.

현재 runserver가 `--noreload`로 실행 중이라면 변경된 백엔드 반영에는 해당 프로세스 재시작이
필요하다. 이 작업에서 서버 재시작은 수행하지 않았다.
