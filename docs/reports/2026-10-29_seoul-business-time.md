# 서울 기준 업무 시간 통일

- 일자: 2026-10-29
- 범위: dev 프론트엔드의 휴가 입력·전송·조회와 업무 시각 표시
- 근거: 사용자의 Asia/Seoul 기준 확인 요청. Notion 접근·갱신 없음.

## 확인과 수정

백엔드 공통 설정은 기존부터 TIME_ZONE=Asia/Seoul, USE_TZ=True이며 휴가 처리 clock은
Django timezone.now를 사용한다. 그러나 프론트는 한국어 표시 언어만 지정하고 브라우저 시간대를
따르고 있었다. 앞선 기본 시간 수정 역시 기기 현지 시간을 사용하여 해외 기기에서 실제 전송
시각이 달라질 수 있었다. 이전 시간 기본값 보고서의 현지 시간 설명은 이번 변경으로 대체한다.

공통 dateTime 유틸리티에서 Asia/Seoul을 지정한 Intl 변환을 사용한다. 시간대 없는 휴가 폼
입력은 현대 한국 업무 시각인 +09:00으로 해석하고 UTC ISO로 전송한다. 초·밀리초 0 고정은
유지한다. 예를 들어 2026-10-29 09:00은 2026-10-29T00:00:00.000Z로 전송되고 화면에서는
다시 09:00으로 표시된다. API의 UTC 표기는 동일한 순간을 표현하며 시각을 9시간 이동시킨 것이 아니다.

휴가 신규 기본 날짜·09:00 검증·재신청·목록 날짜 필터·상세/이력 표시를 서울 기준으로 통일했다.
인사·개인정보·게시판·평가·급여의 처리 이력 표시도 동일 시간대를 지정했다. 인사 오늘 날짜,
급여 기본 연월, 평가 기본 연도 역시 서울 기준으로 계산한다. 생년월일·입사일 등 날짜만 있는
업무 필드는 시각으로 바꾸지 않았다. 기존 함수의 실패/빈값 표시를 유지했다.

백엔드·API 계약·DB 스키마·저장 데이터 변경 없음. 실제 공유 DB의 과거 잘못된 입력 존재 여부나
물리 저장 상태를 검증·수정한 작업은 아니다. 사용자 8080/개발 서버 및 SSH 터널 조작 없음.

## 검증

- 프론트 전체 테스트 69개 통과.
- Asia/Seoul, UTC, America/Los_Angeles 환경에서 휴가/시간대 집중 테스트 각 16개 통과.
- 서울 자정·월말 경계, 오늘/급여 연월, 신청 → ISO 전송 → 재신청 왕복,
  UTC 날짜와 다른 서울 날짜의 목록 필터, 각 업무 처리 이력의 오전 9시 표시를 검증했다.
- lint/build 및 git diff --check 통과. 이번 변경의 브라우저/공유 인프라 검수는 수행하지 않았다.
