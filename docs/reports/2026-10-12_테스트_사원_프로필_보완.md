# 공유 개발 DB 테스트 사원 프로필 보완

- 작업일: 2026-10-12
- 대상: 공유 개발 PostgreSQL `erp_dev.public`
- 범위: 사번 `910001`–`910050`에 연결된 기존 테스트 사원과 Person 50건
- 실행 파일: [`scripts/sql/fill_50_test_employee_profiles.psql`](../../scripts/sql/fill_50_test_employee_profiles.psql)

## 변경 내용

기존 계정 이메일이 `employee<사번>@example.invalid`인 재직 사원 50명을 확인하고, 비어 있던
`persons.gender`, `employees.phone`, `ext_no`, `address`, `bank_code`, `account_no`를
가상 테스트 값으로 채웠다. 성별 값은 실제 인물에 대한 추정이 아니라 테스트 레코드에 임의로
부여한 `M`/`F` 값이다. 전화번호는 `010-0000-xxxx`, 주소는 `(가상 주소)` 표시,
은행 코드는 `TEST`, 계좌번호는 `TEST-<사번>` 형식이다.

기존의 비어 있지 않은 값은 덮어쓰지 않는다. 재직 중인 사원의 `term_date`, 계정의
`last_login`, 계정 권한, 부서, 직급, 생년월일, 입사일은 변경하지 않았다. 대상 Person이
다른 고용 기록과 공유되면 전체 작업이 중단되도록 검증했다.

## 실행 및 검증

1. 읽기 전용 조회에서 대상 계정·사원·Person이 각 50건이고, 위 6개 필드가 각각 50건씩
   NULL인 것을 확인했다.
2. `preview=true`로 트랜잭션을 실행해 Person 50건과 Employee 50건의 갱신 및 결과 검증을
   확인한 뒤 롤백했다.
3. 동일 SQL을 실행해 커밋했다.
4. 커밋 후 읽기 전용 집계에서 대상 50건이 유지되고 6개 필드의 NULL이 모두 0건임을
   확인했다. `TEST` 은행 코드, `TEST-` 계좌번호, 가상 주소, 성별 코드도 각각 50건이었다.

개인정보 및 계좌번호 원문은 로그와 보고서에 기록하지 않았다. 이 데이터는 UI·API 확인용
가상 프로필이며 실제 연락, 우편 발송, 급여 지급에 사용하면 안 된다.
