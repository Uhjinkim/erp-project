# 모듈 담당자 의제 공유 양식

## 사용 원칙

확정 명세와 구현의 차이, 명세 밖 추가 정책, 환경 확인 과제를 구분한다.
담당자는 기여 초안에 조사·수정 결과를 기록하고, 제품 결정이 필요한 항목은 문서 담당자와
제품 결정자에게 전달한다. 제안이나 과거 담당자 확인 기록만으로 공용 정책을 확정하지 않는다.
현재 화면은 이전에 결정한 디자인 시안을 기준으로 재설계하며, 기존 화면 배치를 공용 기준으로 삼지 않는다.

문서 작성은 담당자에게 메시지를 보내는 행위와 별개다. 직접 전송은 별도 지시가 있을 때 수행한다.

## 복사해서 사용하는 양식

### 의제 ID · 제목

- 상태: 조사 필요 / 제품 결정 필요 / 수정 중 / 검증 완료 / 공용 반영 완료
- 주 담당 모듈:
- 협업 모듈:
- 유형: 구현 연동 충돌 / 명세–구현 불일치 / 명세 밖 정책 / 요구 미완료 / 환경 확인
- 관련 규칙·기능 ID:
- 확정 기준: 원문 URL, 저장소 명세, 마지막 확인일
- 현재 동작·근거: 코드 경로, 재현 조건, 관찰 결과
- 영향:
- 작업 항목:
- 결정 요청: 결정이 필요 없는 구현 수정이면 “없음”
- 완료 기준: 권한·상태·성공·실패·회귀 검증과 문서 영향
- 검증 결과: 명령, 결과, 환경, 미검증 범위
- 공유 인프라 영향: 읽기 전용 확인 / DDL / 데이터 변경 / 없음
- 결정·작업 결과: 결정자·날짜·근거, 구현 PR 또는 커밋, 기여 초안 링크

## 이번 통합의 의제

[2026-10-14 최신 모듈 의제](../reports/2026-10-14_module-review-agenda.md)를 사용한다.
기존 [2026-10-12 의제](../reports/2026-10-12_module-review-agenda.md)는 당시 근거 기록으로 보존한다.
각 담당자가 작업을 끝내면 의제 ID를 기여 초안과 PR에 남기고, 문서 담당자가 공용 문서 반영 여부를 검토한다.
