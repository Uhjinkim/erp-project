평가 등급, 게시글 제목 100자, 전사 공지 열람, 급여 원 단위 올림, 승인 휴가의
회수·재승인, 개인정보 수정 요청 상태와 보존 원칙은 확정되었다. 퇴사자 조회와 재입사는

## 저장소 구현 검토 현황 · 2026-10-14

원문 미확정 정책은 위 상태를 유지한다. 급여 코드의 25일·휴일 당김은 PY-02 검토 중인 구현이며
원문 결정 완료로 이동하지 않는다. 추가 충돌은 [최신 모듈 의제](../../reports/2026-10-14_module-review-agenda.md)에
모아 관리한다: BD-01~03, EV-01/02, HR-01~03, PY-01/02, OPS-01, UI-HR/UI-LV/UI-F0.
INT-01과 UI-HR-02는 구현·공용 반영이 해결됐고 실제 서버 브라우저 확인은 남았다.
이번 기록은 저장소 코드 대조이며 Notion 조회·정책 승인 기록이 아니다.

## 2026-10-28 확정 변경과 남은 결정

HR-002의 연락처·주소 승인 요청 전환은 2026-10-27 사용자 결정에 따라 저장소에 반영했다.
Notion 원문 업데이트는 연결 부재로 대기 중이다. HR-01·02 및 HR-03의 특별 처리자·대기 1건 제한은
해결된 것으로 표시하지 않는다. HR_MANAGER 없는 superuser의 메뉴 숨김과 서버 API 허용 차이,
모든 사용자에게 보이는 처리함 메뉴도 후속 결정이다. 평가의 입력 유지·대상 일괄 조회는 구현 개선이며
EV-01/02 제품 정책을 추가 확정한 것은 아니다.


## 2026-10-29 배포 UX 사용자 결정

사용자가 슈퍼유저의 사원·조직 화면 접근 허용을 선택했다. 프론트는 활성 HR_MANAGER 또는
superuser에게 화면을 제공해 기존 서버 API와 일치시킨다. 위 10-28의 메뉴 불일치는 이 결정으로
해소했다. 개인정보 처리함 메뉴는 현재 처리 정책의 HR_MANAGER 또는 superuser로 정리했다.
개별 요청의 특별 처리자·자기 처리 및 다른 HR-03 정책은 추가 확정하지 않았다.
평가·급여 등 다른 업무의 superuser 권한 확장이나 EV/PY 미결 정책의 승인을 의미하지 않는다.
Notion 재조회·업데이트는 수행하지 않았다.
