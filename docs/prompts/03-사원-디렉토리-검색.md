# 03. 사원 디렉토리 검색 (신규, Notion 미확정)

상태: 미착수 — Notion 확인 및 범위 확정 필요

## 사용할 프롬프트

```
workforce 앱에 재직 사원 디렉토리 검색 기능을 구현해줘. 단, 이 기능은 Notion 스펙에
명시되지 않은 신규 항목이라 구현 전에 아래를 먼저 확인해줘:

1. Notion "ERP 프로젝트" 워크스페이스에서 이런 기능(사내 사원 디렉토리/검색)이
   이미 논의됐는지 확인
2. 없다면 미결 사항으로 기록하고, 아래 잠정 범위로 진행할지 나한테 먼저 물어봐:
   - 조회 주체: 재직 중인 모든 사원 (인증만 되면 됨, 별도 역할 불필요)
   - 대상 데이터: tenure_status == ACTIVE 인 Employee만
   - 노출 필드: name, department, position, extension_no (전화/이메일/계좌 등
     민감 정보는 제외)
   - 검색 조건: 이름 부분일치, 부서 필터

아키텍처는 위 두 항목과 동일하게 domain/application/infrastructure/presentation
계층을 따르고, 민감 필드 제외 여부는 presentation/serializers.py에서 명시적으로
통제해줘.

검증은 동일하게 manage.py check / ruff / pytest / makemigrations --check --dry-run.

진행 전 docs/specs/notion/05-open-policies.md에 이 미결 사항을 기록해줘.
```

## 착수 전 참고 사항 (01 구현 중 확인한 것)

- `backend/workforce/presentation/views.py`의 `EmployeeViewSet`이 이미
  `IsHRManagerOrReadOnly` 권한으로 인증된 모든 사용자에게 목록 조회를 허용하고,
  `search`(이름/이메일/사번 부분일치), `dept_no`, `tenure_status` 쿼리 파라미터를
  지원한다. `EmployeeSerializer`가 반환하는 필드는 `emp_no, person_id, name,
  dept_no, position_code, tenure_status, email, phone, extension_no, hire_date,
  term_date`이며 `address`/`bank_code`/`account_no`/`birth_date`/`gender`는
  애초에 포함되지 않는다.
- 즉 이 프롬프트가 요구하는 기능의 상당 부분이 이미 존재한다. 다만 현재는.\scripts\start-dev.ps1
  `email`/`phone`처럼 이 문서가 "민감 정보라 제외"하자고 제안한 필드까지
  모든 인증된 사용자에게 노출하고 있다는 점이 다르다.
- 그래서 실제 작업은 "새 기능 구현"이 아니라 "기존 `EmployeeViewSet` 목록이
  디렉토리 검색 용도로 적절한 노출 범위인지 재검토"에 가까울 수 있다.
  진행 전 이 목록을 그대로 디렉토리 검색으로 쓸지, 필드를 줄인 새 read-only
  엔드포인트/serializer로 분리할지부터 정해야 한다.
