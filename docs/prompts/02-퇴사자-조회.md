# 02. 퇴사자 조회 (인사관리자 전용)

상태: 미착수

관련: `FN-HR-006`~`FN-HR-010` 그룹, `docs/specs/notion/05-open-policies.md`에서
"퇴사자 조회와 재입사는 인사관리자 기능"으로 확정됨.

## 사용할 프롬프트

```
workforce 앱에 퇴사자 조회 API를 구현해줘 (FN-HR-006~010 그룹, 05-open-policies.md에서
인사관리자 전용으로 확정된 기능).

범위:
- 조회 주체: 인사관리자만 (기존 workforce/presentation/permissions.py의
  IsHRManager 재사용)
- 대상 데이터: Employee.tenure_status == TERMINATED 인 사원 목록
- 검색/필터 조건: 이름(person.name), 부서(department), 퇴사일 범위(term_date),
  사번(employee_no) — 필요한 조건 있으면 알려줘, 없으면 이 네 가지로 진행

아키텍처:
- application/에 read 전용 유스케이스(예: list_terminated_employees) 추가,
  기존 WorkforceQueryGateway 패턴처럼 필요하면 ports.py에 조회 메서드 추가
- infrastructure/gateways.py에 ORM 쿼리 구현 (Employee.objects.filter(
  tenure_status=Employee.TenureStatus.TERMINATED) 기반)
- presentation/views.py에 permission_classes = [IsHRManager]인 목록 API 추가,
  쿼리 파라미터로 필터 받기
- 목록이라 페이지네이션 필요 여부도 판단해서 적용

검증:
- backend/에서 uv run python manage.py check, ruff check ., pytest,
  makemigrations --check --dry-run
- 일반 사원 접근 시 403, 인사관리자 접근 시 필터 결과가 맞는지 테스트

추적성:
- 구현 대응표에 "퇴사자 조회" 항목을 "현재 구현"으로 이동하고 관련 FN-HR ID 명시
```

## 착수 전 참고 사항 (01 구현 중 확인한 것)

- `EmployeeViewSet`(`backend/workforce/presentation/views.py`)은 이미
  `IsHRManagerOrReadOnly` 권한으로 `tenure_status` 쿼리 파라미터 필터를
  지원한다. 즉 `GET /api/workforce/employees/?tenure_status=퇴사`가
  이미 동작할 수 있다 — 단 이 목록은 **인사관리자가 아니어도 읽기 가능**하다는
  점이 "퇴사자 조회는 인사관리자 전용" 정책과 어긋난다.
- 그래서 이 프롬프트를 실행하기 전에, 기존 `EmployeeViewSet` 목록에서
  `TERMINATED` 상태를 인사관리자 이외에는 필터링해서 못 보게 막을지,
  아니면 별도 엔드포인트로 분리해 기존 재직자 검색 목록은 그대로 둘지
  먼저 정해야 한다. 별도 엔드포인트 분리 쪽이 기존 동작을 안 건드리므로
  더 안전하다.
