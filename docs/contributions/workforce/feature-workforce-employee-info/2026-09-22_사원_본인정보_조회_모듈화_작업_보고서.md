# 사원 본인 정보 조회(FN-HR-001) 모듈화 작업 보고서

- 작업일: 2026-09-22
- 작업 범위: FN-HR-001(본인 정보 조회) 구현을 `workforce` 도메인/애플리케이션 계층으로
  모듈화, 로컬 오프라인 실행 환경 정비
- 관련 문서: `docs/specs/notion/workforce-implementation-map.md`,
  `docs/prompts/01-본인-정보-조회.md`

## 1. 배경

`GET /api/auth/me/`(accounts 앱)가 세션 식별용으로 사번·이름·부서·직급만 반환하던 것을
FN-HR-001 범위(생년월일, 연락처, 주소, 급여계좌, 입·퇴사일 등 본인 인사정보 전체)로 확장했다.
1차 구현은 `accounts/serializers.py`가 `workforce`의 ORM 모델(`Employee`, `Person`)을 직접
조회하는 방식이었는데, 이는 `vacation` 앱이 이미 따르고 있는 "다른 앱은 `workforce`의
`WorkforceQueryGateway` 포트를 거쳐서만 조회한다"는 경계를 깨는 구조였다. 이번 작업에서
`vacation/`과 동일한 방식으로 `workforce` 내부에 도메인/애플리케이션/인프라 계층을 두고,
`accounts`는 그 계층을 통해서만 조회하도록 재구성했다.

## 2. 모듈 구조

### workforce (신규 계층)

- `domain/policies.py`: `EmployeeProfile` frozen dataclass 추가. ORM·Django import 없는
  순수 값 객체로, 본인 정보 조회 응답의 필드 계약을 정의한다.
- `application/ports.py`: `EmployeeProfileGateway` Protocol 추가
  (`employee_profile(employee_no) -> EmployeeProfile | None`).
- `application/services.py`: `get_employee_profile(employee_no, gateway)` 유스케이스 추가.
  포트에 위임만 하는 얇은 read 유스케이스이며, `employee_has_role`과 동일한 패턴이다.
- `infrastructure/gateways.py`: `DjangoWorkforceQueryGateway.employee_profile()` 구현 추가.
  기존 `WorkforceQueryGateway`/`RoleCommandGateway` 구현체를 재사용해 `EmployeeProfileGateway`도
  구조적으로 만족시킨다(파이썬 Protocol은 구조적 타이핑이므로 별도 클래스를 만들지 않았다).

### accounts (호출부)

- `serializers.py`의 `CurrentUserSerializer.get_employee()`가 더 이상 `workforce`의 ORM
  모델을 직접 참조하지 않고, `workforce.application.services.get_employee_profile()`을
  호출해 받은 `EmployeeProfile`을 `dataclasses.asdict()`로 변환해 응답한다.
  `employee_no` 필드만 기존 API 계약(`emp_no`)에 맞춰 키를 바꿔준다.
- `views.py`의 `CurrentUserView`는 더 이상 `employee__person/department/position`을
  select_related할 필요가 없어져 `select_related("employee")`로 단순화했다(프로필 조회는
  게이트웨이가 자체 쿼리로 처리한다).

## 3. 아키텍처 경계 확인

- `backend/tests/test_workforce_architecture.py`(계층 간 금지 import를 검사하는 architecture
  test)가 그대로 통과해 `domain/`이 여전히 순수 Python임을 보장한다.
- `accounts`는 여전히 `workforce.application.services`와
  `workforce.infrastructure.gateways.DjangoWorkforceQueryGateway`에 의존하는데, 이는
  `accounts/presentation` 권한 체크(`IsHRManager`)가 이미 쓰던 것과 동일한, 기존에
  허용된 의존 방향이다(`accounts` → `workforce`, 역방향 없음).

## 4. 로컬 오프라인 실행 환경 정비 (검증 과정에서 발견한 별개 버그 수정)

FN-HR-001을 실제 브라우저에서 눈으로 확인하는 과정에서 아래 기존 버그를 발견해 함께 고쳤다.
모두 이번 기능과 무관하게 이미 존재하던 문제였다.

- `scripts/start-dev.ps1`: 이 저장소가 쓰는 Windows nginx 빌드는 기본 임시 경로가
  `temp/client_body_temp` 등으로 설정돼 있는데, 스크립트가 이 디렉터리를 미리 만들지 않아
  `-t` 설정 검증부터 실패했다. 실행 전 다섯 개 임시 디렉터리를 생성하도록 수정했다.
- `backend/config/demo_settings.py`: macOS 전용 하드코딩 경로(`/private/tmp/...`)를
  `tempfile.gettempdir()` 기반으로 바꿔 Windows에서도 동작하게 했다. 또한 레거시 테이블
  migration이 실제 PostgreSQL 기준 state-only라 로컬 SQLite에는 테이블이 생성되지 않는
  문제가 있어, `config/settings/test.py`와 동일하게 `MIGRATION_MODULES`를
  `accounts`/`vacation`/`workforce`에 대해 `None`으로 설정해 `--run-syncdb`로 테이블을
  직접 생성하도록 했다.
- `backend/config/settings/development.py`: `CSRF_TRUSTED_ORIGINS`가 어디에도 설정돼
  있지 않아, 문서화된 "backend와 frontend를 각각 따로 실행"하는 표준 개발 흐름
  (Vite `:5173` → Django `:8000`)에서 로그인 등 상태 변경 요청이 전부 Origin 불일치로
  403이 나는 문제가 있었다. `localhost`/`127.0.0.1`의 `5173`, `8080` origin을
  `CSRF_TRUSTED_ORIGINS`에 추가했다. nginx(`:8080`)로 묶어 실행할 때는 origin이 하나라
  원래 문제가 없었지만, nginx 없이 backend/frontend만 따로 실행하는 표준 흐름에서는
  항상 재현되는 버그였다.

## 5. 검증

- `uv run python manage.py check` 통과
- `uv run ruff check .` 통과
- `uv run pytest` 28개 전체 통과 (신규 유닛 테스트 2건 포함)
  - `test_get_employee_profile_reads_through_workforce_application_layer`:
    애플리케이션 계층 유스케이스를 HTTP 없이 직접 검증
  - `test_get_employee_profile_returns_none_for_unknown_employee`
  - 기존 `test_me_response_includes_own_profile_fields`(엔드투엔드) 계속 통과
- `uv run python manage.py makemigrations --check --dry-run`: 변경 없음
- 로컬 SQLite 오프라인 환경(`config.demo_settings`)에서 Vite(`:5173`) → Django(`:8000`)
  프록시 경유 로그인과 `GET /api/auth/me/` 실호출로 응답 필드 확인
- 사원·부서 샘플 데이터로 `GET /api/workforce/employees/`, `PATCH
  /api/workforce/employees/{emp_no}/` 등 기존 workforce API의 조회·수정도 회귀 없음을 확인

공유 PostgreSQL에는 migration, seed, 계정 생성, 데이터 변경을 일절 실행하지 않았다. 이번 검증에
쓰인 샘플 계정(`demo@example.com` 등)은 로컬 SQLite 데모 DB(`%TEMP%/erp-project-demo.sqlite3`)
에만 존재한다.
