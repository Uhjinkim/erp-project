# 인사평가 화면 테스트 시나리오 체크리스트

- 대상: `evaluation` 모듈
- 환경: 로컬 개발 서버 + 공유 개발 DB `erp_dev` (SSH 터널)
- 작성: 2026-10-08

## 0. 2026-10-08 사용자 결정 반영 사항

`README.md`(팀 확정본) 이후 다음이 정해져 구현에 반영되었다. README 갱신은 팀에서 한다.

- 인사관리자이면서 부서장인 사원도 평가자가 된다. 그 평가의 확정은 다른 인사관리자가 한다
  (README의 "인사관리자는 평가자가 될 수 없다"를 대체).
- 근무 3개월 이하 사원은 평가 대상이 아니다. 근무 기간은 평가 기준일(지난 연도는 12/31,
  올해는 오늘)까지로 센다. 정확히 3개월이면 제외된다. 코드 `insufficient_tenure`(400).
- 회사에 계약직이 없고 DB에도 고용형태 정보가 없어 고용형태 규칙은 두지 않는다.
- 평가 기간(12월 둘째 주 ~ 12/31 안)은 아직 정하지 않았고 구현하지 않는다. 현재는 기간 제한 없이
  작성·제출·확정할 수 있다.

## 1. 사전 준비

### 1-1. 서버 실행

1. SSH 터널을 연다(PostgreSQL·Redis). 방법은 루트 `README.md`의 터널 절을 따른다.
2. 저장소 루트에서 통합 개발 서버를 실행한다.

   ```powershell
   .\scripts\start-dev.ps1
   ```

3. 브라우저에서 `http://localhost:8080` 을 연다.
4. 상단 연결 상태에서 백엔드·PostgreSQL·Redis·사원 연동·End to end가 모두 **연결됨**인지 확인한다.
   하나라도 끊겨 있으면 업무 화면이 비활성화된다.

### 1-2. DB 상태 확인 (읽기 전용)

`backend/`에서 실행한다.

```bash
uv run python manage.py showmigrations evaluation
```

- `0001_initial`, `0002_evaluation_workflow` 가 `[X]` 여야 한다.
- `0003_history_changed_at_timestamp` 는 적용 전이어도 테스트에는 영향이 없다. 적용은
  `evaluation_history` 테이블 소유자가 한다.

### 1-3. ⚠️ 필수 조치 ①: `evaluation_history` 권한

2026-10-08 점검 결과 `evaluation_history` 는 `0002`를 적용한 계정 소유이고 다른 개발자 DB 계정에는
권한이 없다. 이 상태에서는 **평가 작성이 500 오류로 실패**한다(트랜잭션이 취소되어 데이터는 남지
않음). 테이블 소유자 또는 DB 관리자가 실행한다.

```sql
-- <db_role> 은 실제 개발자 계정 또는 공용 그룹으로 바꾼다.
GRANT SELECT, INSERT, UPDATE ON evaluation_history TO <db_role>;
GRANT USAGE, SELECT ON SEQUENCE evaluation_history_history_id_seq TO <db_role>;
```

권한 확인(읽기 전용, `backend/`에서 실행). `(True,)` 이면 된다.

```bash
uv run python manage.py shell -c "from django.db import connection; c = connection.cursor(); c.execute(\"select has_table_privilege('evaluation_history', 'INSERT')\"); print(c.fetchone())"
```

### 1-4. ⚠️ 필수 조치 ②: 테스트 사원의 입사일

`erp_dev` 사원 50명의 입사일이 모두 **2026-09-22** 이다. 근무 3개월 이하 제외 규칙 때문에 지금은
올해·작년 모두 평가 대상이 한 명도 없고, 부서장 화면에 작성 폼이 나오지 않는다. 테스트하려면 DB
관리자 승인을 받아 테스트용 사원의 입사일을 3개월 이전으로 바꾼다. 예:

```sql
-- 승인을 받은 뒤 실행. 테스트에 쓰는 사원만 바꾼다.
UPDATE employees SET hire_date = DATE '2025-01-02'
WHERE emp_no IN (910001, 910008, 910009, 910011, 910012, 910013, 910014, 910026, 910038, 910039);
```

`2025-01-02` 로 두면 올해(2026)와 작년(2025) 평가 모두 만들 수 있다. 작년 평가만 막아 보려면
일부 사원을 `2025-10-01` 이후로 둔다.

## 3. 시나리오

각 항목에 ✅/❌ 와 메모를 남긴다. API 응답은 브라우저 개발자 도구 Network 탭에서 확인한다.

### A. 화면·권한 기본

- [ ] **A1. 부서장 작성 폼** — 910011 로그인 → `인사평가` 탭.
  기대: "평가 작성" 폼, 평가 대상에 입사 3개월이 지난 개발팀 부서원만 나온다. 연도는 올해·작년.
- [ ] **A2. 근무 3개월 이하 제외** — 1-4에서 입사일을 바꾸지 않은 개발팀원은 목록에 없다.
  API로 직접 작성하면 `insufficient_tenure`(400).
- [ ] **A3. 인사관리자(부서장 아님) 화면** — 910002 로그인 → 작성 폼 없음, 평가 목록만 보임.
- [ ] **A4. 재배정 후보** — 910002 로그인 상태에서 `/api/evaluations/evaluator-candidates/`.
  기대: 910001, 910011, 910026, 910038 (인사관리자인 부서장 910001 포함).
- [ ] **A5. 일반 사원 화면** — 910039 로그인 → 작성 폼 없음, 목록 비어 있음.

### B. 작성·수정·제출 (평가자)

- [ ] **B1. 작성** — 910011: 대상 910012, 올해, 점수 85.5, 의견 입력 → `작성중으로 저장`.
  기대: `작성중`, 85.50점, 등급 A. 상세 처리 이력에 "작성".
- [ ] **B2. 중복 작성 차단** — 같은 대상·연도 재작성 → "해당 연도의 평가가 이미 존재합니다."(409)
- [ ] **B3. 등급 경계** — 점수 90 → S, 89.99 → A, 70 → B, 69.99 → C.
- [ ] **B4. 의견 유지** — 점수만 바꿔 저장해도 의견이 남는다.
- [ ] **B5. 제출** — `제출` → `제출` 배지, 수정 폼 사라짐.
- [ ] **B6. 대상자 비공개** — 910012 로그인 → 목록 비어 있음(EV-005).

### C. 반려·확정 (인사관리자)

- [ ] **C1. 반려 사유 필수** — 910002: 사유 없이 `반려` → "처리 사유를 입력하세요."
- [ ] **C2. 반려** — 사유 입력 후 `반려` → `반려` 배지, 이력에 사유.
- [ ] **C3. 재제출** — 910011: 수정 → `제출`.
- [ ] **C4. 확정** — 910002: `확정` → `확정` 배지, 확정자 910002.
- [ ] **C5. 대상자 공개** — 910012 로그인 → 확정 평가가 보이고 처리 이력은 안 보인다.
- [ ] **C6. 확정 후 수정 불가** — 910011: 상세에 수정 폼 없음.

### D. 확정 취소(정정)

- [ ] **D1. 확정 취소** — 910002: 사유 입력 → `확정 취소` → `반려`, 확정자 비워짐.
- [ ] **D2. 대상자 다시 비공개** — 910012: 목록에서 사라짐.
- [ ] **D3. 정정 후 재확정** — 910011 수정·제출 → 910004 `확정`. 이력에 확정·확정 취소·재확정.

### E. 평가자 재배정

910011이 910013 평가를 작성·제출한 뒤 진행한다.

- [ ] **E1. 재배정** — 910002: 새 평가자 910026 선택, 사유 입력 → `평가자 재배정`.
  기대: 현재 평가자 910026, 상태 `작성중`.
- [ ] **E2. 이전 평가자 접근 차단** — 910011: 목록에서 사라짐.
- [ ] **E3. 새 평가자 이어받기** — 910026: 기존 점수·의견이 보이고 수정·제출 가능.
- [ ] **E4. 부서장 아닌 사원 지정 불가** — API로 `evaluator_no: 910039` →
  `evaluator_must_be_department_head`(403). 화면 후보에는 없다.

### F. 평가 제외

- [ ] **F1. 제외** — 910002: 확정 전 평가에 사유 입력 → `평가 제외` → `제외`, 점수 보존.
- [ ] **F2. 제외 상태에서 확정 불가** — 확정 버튼 없음.
- [ ] **F3. 제외 취소** — `제외 취소` → 직전 상태로 복원.

### G. 인사관리자이자 부서장 (2026-10-08 결정)

- [ ] **G1. 작성** — 910001 로그인 → 작성 폼에 인사팀원(910008 등)이 나온다. 910008 평가 작성·제출.
- [ ] **G2. 본인 확정 불가** — 910001: 상세에 `확정` 버튼이 없다. API로 확정하면
  `confirmation_not_allowed`(403).
- [ ] **G3. 다른 인사관리자 확정** — 910002: `확정` → 확정자 910002.
