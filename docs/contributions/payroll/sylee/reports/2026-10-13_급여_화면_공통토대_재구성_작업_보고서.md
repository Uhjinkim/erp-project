  `frontend-module-delivery.md`)에 맞춰 F7 배정 화면 5개로 분리

## 1. 요청 사항

공통 디자인 기준에 맞춰 급여 모듈의 메뉴 탭별 세부 화면을 반영한다.

- 급여 정산 기간 목록: 담당자 판단 후 제안
- 급여 정산 생성: 급여 관리의 급여 생성 부분 이동
- 사원별 정산 항목: 담당자 판단 후 제안
- 급여 확정·정정: 담당자 판단 후 제안
- 내 급여명세: 내 급여 부분 이동

## 2. 결정 사항(사용자 확인)

| 항목 | 결정 |
| --- | --- |
| 기간 목록 표시 | 정산월별 건수만(대상·작성중·확정·미작성). 금액 합계는 넣지 않음 |
| 확정 버튼 위치 | 급여 확정·정정 화면에만 |
| 생성 화면 버튼 | "작성중으로 저장", 성공 시 항목·확정 화면 이동 링크 |
| 이력 위치 | 항목·확정 화면에서 Drawer. 내 급여명세는 본인용 이력 유지 |
| 기본 진입 화면 | 내 급여명세 |
| F0 소유 `ModuleScreen.tsx` | sylee에서 최소 수정 후 기여 문서에 F0 검토 요청 |

## 3. 화면별 구성

- **급여 정산 기간 목록**(`payroll-periods`): 백엔드에 기간 테이블·일괄 생성 API가 없어,
  급여를 연·월로 묶어 표로 보여준다. 현재 월은 급여가 없어도 표시한다. 각 행에서 정산 항목,
  확정·정정, 미작성이 있으면 정산 생성으로 이동한다(`?period=`). 미작성은 현재 재직 기준이라
  과거 월에는 이후 입사자가 포함될 수 있음을 화면에 안내했다.
- **급여 정산 생성**(`payroll-create`): 부서→사람, 정산월(월 입력 하나로 통합), 지급일(선택),
  구성항목 금액. 옆에 그 달의 미작성 사원 목록을 두고 "선택"하면 폼이 채워진다. 본인은
  선택할 수 없다. 서버 필드 오류는 해당 입력에 연결한다.
- **사원별 정산 항목**(`payroll-item`): 부서·사람·정산월·상태 필터, 목록 표, 오른쪽에 선택한
  급여명세서. 작성중이면 지급일·구성항목 편집, 확정이면 PDF·엑셀 저장과 정정 안내.
  `?statementId=`로 특정 급여를 바로 연다.
- **급여 확정·정정**(`payroll-confirm`): 정산월·부서 필터, "확정 대기(작성중)"와 "확정 완료"
  두 표. 확정은 차인지급액을 보여주는 확인 창, 확정취소는 사유 입력 창. 취소 후 "사원별 정산
  항목에서 정정하기" 링크를 보여준다. 본인 급여 버튼은 비활성이다.
- **내 급여명세**(`payslip`): 월 목록과 선택한 명세서(기본은 최신 월), PDF 저장·인쇄, 엑셀
  저장, 이력.
- 급여담당자 전용 4개 화면은 다른 사용자에게 안내와 내 급여명세 링크를 보여준다.

## 4. 구현

- `features/payroll/`
  - `PayrollScreen.tsx`: 공개 진입점. `route.screenId`로 화면을 고르고, query가 바뀌면 화면을
    다시 만든다.
  - `screens/`: 화면 5개
  - `components/`: `PayslipView`, `AmountFields`, `EmployeePicker`, `HistoryDrawer`
  - `hooks/`: `usePayrollQuery`(이전 응답 무시), `useManagerData`, `usePayslipPrint`
  - `model.ts`: 기간 집계·미작성·부서 분류 등 순수 함수
  - `payroll.module.css`: 공통 토큰 기반 지역 스타일
- 공통 UI(`Card`, `Table`, `Button`, `TextInput`, `Select`, `Textarea`, `Alert`, `Badge`,
  `EmptyState`, `ErrorState`, `Spinner`, `ConfirmDialog`, `Modal`, `Drawer`)를 사용했다.
- 처리 중 버튼 비활성과 중복 요청 방지는 모듈에서 처리했다.
- PDF 인쇄는 `styles/print.css`의 `body.payroll-printing`·`.payslip--printing` 규칙을 그대로
  쓰고, 버튼·상태 배지는 모듈 CSS의 인쇄 규칙으로 숨긴다.
- `registration.ts`의 `entry`를 `payslip`으로 바꿨다.
- `app/ModuleScreen.tsx`(F0 소유): 급여 모듈 화면을 `PayrollScreen`으로 넘기도록 최소 수정했다.
- `components/PayrollPanel.tsx`를 삭제했다.
- 화면 재구성 자체의 백엔드·API 변경은 없다(이력 사유 형식 변경은 5절).

## 5. 추가 수정(같은 날 요청)

1. **정산 생성 선택 동작**
   - 오른쪽 미작성 목록에서 사원을 고르면 폼 위치로 스크롤하고 첫 금액 칸에 커서를 둔다.
   - 사람을 고르거나 정산월을 바꿀 때 그 사람의 직전 월 급여(작성중·확정 무관)가 있으면
     구성항목 금액을 불러오고 "지난달(…) 급여 금액을 불러왔습니다" 안내를 보여준다.
   - 지급일은 월마다 달라 불러오지 않는다. 직전 월 급여가 없으면 금액 칸을 비운다.
   - 사용하지 않던 생성 화면 `empNo` query는 없앴다.
2. **이력 Drawer 바깥 클릭으로 닫기**
   - 공용 `Modal`은 F0 소유라 수정하지 않았다. 급여 `HistoryDrawer`가 열려 있는 동안 문서
     click을 받아, 대상이 열린 `<dialog>`이고 좌표가 상자 밖(배경)이면 닫는다.
   - 공용 prop 추가를 F0에 요청했다(기여 문서).
3. **수정 이력 사유를 줄 단위로 기록**(백엔드 `PayrollService`)
   - 쉼표 대신 줄바꿈으로 구분한다.
   - 순서는 지급일 변경, 지급 항목, 공제 항목이고, 각 묶음 안은 `PAYSLIP_ORDER`를 따른다.
   - 화면은 `white-space: pre-line`으로 줄바꿈을 표시한다.
   - 255자 제한은 그대로다. 기존 쉼표 형식 이력은 바꾸지 않았다(공유 DB 쓰기 없음).
